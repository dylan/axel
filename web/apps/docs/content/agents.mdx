An **agent** is a name you can call (`@aaron`), a key that signs everything it does, and a
profile that says how to run it. Agents are reusable: the same aaron works on many threads,
over months.

## Create one

```bash
axel agent new aaron --harness claude --model opus --skills '*' --color orange
axel agent ls
axel agent show aaron       # profile, policy and the owner attestation
```

Creating an agent:

1. generates an **Ed25519 keypair** and stores the private key in the macOS keychain;
2. signs an **attestation** with your owner key: "this key is my agent aaron";
3. records the profile.

| Profile | |
|---|---|
| `--harness` | `claude`, `codex` or `opencode`. |
| `--model` | Optional; the harness default otherwise. |
| `--skills` | Skills to install for it, comma-separated, or `*` for all of them. |
| `--prompt` | A standing prompt added to every session. |
| `--color` | How it shows up in the dashboard and in `@mentions`. |
| `--runtime-mode` | How much it may do alone; see [Permissions and budgets](/policies). |
| `--host` | Where it runs unless told otherwise; see [Remote hosts](/remote-hosts). |

Change any of it later with `axel agent edit aaron …`. `axel agent archive aaron` retires
an agent and keeps its key and history.

## Why keys

Everything an agent does on a thread (a reply, a tool call, a message to another agent) is
an event signed with its key. That makes three things possible:

- **Attribution you can check.** A thread shows who did what, and a copy of it on another
  machine can verify that it was really aaron.
- **Safe delegation.** On a remote machine, aaron's key never leaves home: the machine gets a
  short-lived grant to sign for him on one thread. See [Remote hosts](/remote-hosts#keys-never-leave-home).
- **Multiplayer threads.** Threads merge across machines and people by their signed events.

## Inside a session

Axel tells the agent who it is through its environment:

| Variable | |
|---|---|
| `AXEL_AGENT_NAME` | Its name. |
| `AXEL_AGENT` | Its public key. |
| `AXEL_THREAD` | The thread it works on. |
| `AXEL_SESSION` | This session. |

It also installs the **axel skill**, which teaches the agent how to message other agents,
report its status and read its inbox, and an **MCP server** with the same tools. See
[The agent's toolkit](/agent-toolkit).

## Inbox

Every identity, you included, has an inbox: messages that mention it, permission requests,
questions, and status from its sessions. `axel inbox` prints yours;
`axel inbox --agent aaron` prints aaron's. When anything needs you, `axel` opens on the
inbox instead of the launcher.
